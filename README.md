## 一、产品名称

**校园机会雷达** —— 把来源不同、质量不一、字段残缺的校园信息，整理成新生能看懂、能直接行动的决策面板。

## 二、主要解决的问题

**1. 同一事件多记录与版本覆盖**

- **现象**：同一事件可能被拆分为多条记录，后续记录会修正前序记录的时间、地点或内容。
- **风险**：若未进行事件聚合或未识别最新版本，用户可能依据旧时间、旧地点行动，导致无效到场。
- **处理原则**：按事件维度聚合记录，标注版本与更新时间，默认展示最新有效信息，并保留变更历史。

**2. 时效状态与可用性分离**

- **现象**：主活动已结束或报名已截止，但仍存在回放、候补、短期资源等可用入口。
- **风险**：若统一标记为"已结束"，会遗漏仍可参与或获取的资源。
- **处理原则**：将"主活动状态"与"后续可用状态"分离，支持"已结束 / 可回放 / 可候补 / 资源有效期内"等细分状态。

**3. 关键字段缺失与禁止推断**

- **现象**：部分记录缺少报名时间、费用、截止时间、场地、地点等关键决策字段。
- **风险**：用户无法判断截止时间与参与成本，影响参与决策。
- **处理原则**：显式展示"未提供""待确认""未确定"等状态，不得编造或主观推断；必要时标记为待补充字段。

**4. 信息质量分层与可疑内容处置**

- **现象**：信息来源质量不一，部分内容存在诱导、主题错配或商业推广。
- **风险**：原样展示可能误导用户；直接删除又可能违背开放发布原则。
- **处理原则**：建立质量分级与风险提示机制；对高风险内容添加警示、限制展示范围或转人工复核；对开放发布内容保留，但明确标注来源与风险。

## 三、核心功能

参考现行成熟工具，做出了如下基础内容：

| # | 功能 | 说明 |
| --- | --- | --- |
| 1 | **信息流 + 多维筛选** | 6 个快捷筛选（即将截止 / 可候补 / 零基础新生 / 今天 / 长期有效 / 需核实）+ 关键词搜索（支持拼音、首字母、近义词、错字容错）；桌面端另提供侧栏平铺筛选（来源 / 类型 / 适合谁 / 时间） |
| 2 | **详情页** | 统一字段表（活动时间 / 报名截止 / 地点 / 面向对象 / 人数 / 费用 / 每周投入）+ 倒计时 + **题目原文对照**，缺失字段显示「未注明」而非留空 |
| 3 | **收藏与我的日程** | 一键收藏，进入「我的日程」，按截止时间排序；刷新、重开浏览器均保留 |
| 4 | **学生自主发布** | 可发布组局 / 活动 / 招募 / 资料，发布内容**进入同一条信息流**并带「学生自发」标记，与官方信息一同参与筛选和排序 |
| 5 | **AI 状态整合** | 依据时间与材料自动推导状态：可报名 / 即将截止 / 已截止 / **可候补** / **长期有效** / 进行中 / **待回放** / 已结束 |
| 6 | **留言提问** | 每条信息下可提问（如"场地确认了吗""还缺人吗"），回应题 23「报名后拉群」这类需要沟通的场景；不引入私信 IM |

## 四、运行方式

**无需安装、无需构建、无需服务器** —— 纯静态前端。

- **在线访问（推荐）**：<https://dwtlxxx.github.io/04260610/>
- **本地访问**：在项目根目录起任意静态服务器后访问 `index.html`
  ```bash
  # 任选一种，项目根目录执行
  python -m http.server 8000
  npx serve .
  ```
  然后打开 <http://localhost:8000/>

> ⚠️ **注意**：本项目使用 ES Module（`<script type="module">`），受浏览器同源策略限制，
> **不能直接双击 `index.html` 打开**（`file://` 协议会被 CORS 拦截）。
> 请使用上面的在线地址，或本地起一个静态服务器。

**技术栈**：HTML + CSS + 原生 JavaScript（ES Module），零依赖、零构建。
**数据存储**：浏览器 localStorage（收藏 / 发布 / 留言 / 举报 / 主题 / 视图偏好）。
**浏览器要求**：Chrome / Edge / Firefox / Safari 等现代浏览器。

## 五、自主设计的实用或创新内容

### ★ 创新 1：信息可信度与风险提示引擎（核心创新）

题目要求兼顾「开放发布」与「平台使用秩序」。**直接删除可疑信息违背开放发布，原样展示又可能误导同学**，所以我选择第三条路：**仍然展示，但把问题明确标出来，让用户自己判断**。

规则引擎基于客观事实，输出**提示**而非**判决**：

| 规则 | 触发条件 | 输出 |
| --- | --- | --- |
| 要求跳转平台外私人联系 | 内容要求添加私人微信 | ⚠ 高风险提示 |
| 含商家推广 / 购买链接 | 正文指向优惠与购买链接 | ⚠ 高风险提示 |
| 标题与正文主题不符 | 标题写技术交流，正文是商家优惠 | ⚠ 提示 |
| 线下活动缺地点 | 无地点且类型为活动 / 组局 | ⚠ 提示（含"地点待确认"状态） |
| 无机构背书 | 学生个人发布 | ℹ 说明 |
| 报名截止未注明 | 无截止时间且非长期招募 | ⚠ 提示 |
| 竞赛费用未提供 | 涉及支出的竞赛缺费用 | ⚠ 提示 |
| 资源链接有效期临近 | 网盘提取信息有有效期 | ⚠ 提示 |

并给出**四档可信度**（机构发布 / 学生发布 / 信息待补 / 建议核实），在列表页一眼可辨。配套提供**举报入口**，形成处理闭环。

### ★ 创新 2：系列信息合并与更新覆盖

把"补充通知"合并进主条目，**只显示生效后的版本**，并明确告知"本条已被补充通知更新"。

- 01 + 09 → 详情页只显示 **9/21 19:30 / 实验楼 A402**（不再显示已作废的"9/20 起每周六"）
- 03 + 20 → 直接标出 **已满：开发** / **仍在招：设计、材料**，避免同学白投开发岗

这一条直接防住了"按旧通知跑错时间、跑错楼"的真实事故。

### ★ 创新 3：字段完整度量化

用 0–100 分量化每条信息的完整度（权重按"是否影响决策"分配：活动时间与报名截止各 25 分，地点 20 分，面向对象 15 分），并**直接列出缺哪些字段**。让"这条信息靠不靠谱"从主观感觉变成可比较的指标。

### ★ 创新 4：双端差异化形态

| | 手机端 | 电脑端 |
| --- | --- | --- |
| 结构 | 卡片流 + 底部导航 + 悬浮发布 | 侧栏导航 + **等高卡片网格** + 右栏总览 |
| 信息密度 | 一屏 2–3 条，聚焦单条 | **一屏 4~6 条**（等高网格，两列自适应），对齐后可快速扫读 |
| 交互 | 拇指可达、碎片化浏览 | 左侧栏收起时是**图标轨道**、鼠标移到轨道上展开（不挤压内容）、排序切换、筛选器平铺 |
| 右栏常驻 | — | 紧急提醒 + 我的日程 + **AI 整合助手** |

两端**共用同一套数据与判定逻辑**，因此收藏、发布、状态判定完全同步；断点变化实时重渲染，也可手动切换（方便投影演示）。

> **左侧栏的形态与两次修正**：顶栏右上角的手动开合按钮已按反馈删除，改为鼠标移到左侧栏即展开。
> 收起态现在是 56px 的**图标轨道**（保留各板块的抽象图标 + 当前板块高亮），鼠标移到轨道上展开为完整面板，
> 移开自动收回；纯 CSS（`:hover` / `:focus-within`）驱动，鼠标扫过不触发任何重渲染。
>
> 这里踩过两个坑，值得记录：
> ① 最初收起态是"完全隐藏 + 屏幕左边缘 16px 隐形热区"。**全屏时能用是因为指针撞到屏幕边缘会被挡住、
>    从而碰巧命中那条热区；窗口化（非全屏）时没有这个物理边界，指针很容易差十几像素，
>    表现就是"鼠标移过去没反应、展开不了"**。改成可见的图标轨道后，悬停目标又大又看得见，问题消失。
> ② 展开采用 `position: fixed` 浮层而不是挤压布局：若留在文档流里，每次鼠标扫过左边都会重排信息流
>    （等高网格若在文档流里展开也会引起重排）。轨道占位由 `.shell` 的 `padding-left` 预留，展开只改宽度，主区纹丝不动。
>    文字与筛选面板在轨道态用 `opacity` 隐藏（而非 `display:none`），
>    这样它们仍在 Tab 顺序里，键盘用户 Tab 进侧栏时会触发 `:focus-within` 展开，焦点不会落在看不见的地方。

### ★ 创新 5：双主题（浅色 / 深色）

默认**跟随系统**，可手动三态切换（跟随系统 → 浅色 → 深色）。

实现上用 **CSS 设计令牌**把颜色抽成变量，因此"两种结构 × 两套色板"只需维护 2 套结构 + 2 套变量，而不是 4 套界面。深色模式是**独立设计的一套色板**：文字不用纯白避免刺眼、品牌色提亮、状态色与风险色单独调校以保证在深色背景上仍可辨（这是本产品核心信息载体，看不清等于功能失效），卡片层级改用边框而非阴影。

**页面底部色带**：底部原本只是一块纯灰、手机上再压一条纯白的导航条，收尾很生硬。现在用 `body::before` 在视口底部铺一条固定渐变色带（透明 → 底部色），颜色不是另加的一种，而是 `color-mix(品牌色 + 页面底色)` 算出来的（浅色 16% / 深色 22%），因此自动跟随主题、也自动与品牌色协调。它放在 `z-index:-1`（内容之下、画布底色之上），所以卡片始终保持纯净，只有卡片间的空隙透出色带；手机上这条色带正好落在半透明+模糊的底部导航条下面，导航条吃到同一份色调，于是"底部导航 + 页面收尾"读起来是同一块区域。左侧栏收起时背景透明，色带也能一路延伸到左下角。

**底部"呼吸光晕"与滚动节奏**：底部的律动装饰换过三代 —— 最早是 canvas 逐帧画波形，反馈"细线还是太丑"；随后试过雷达扩散，也被否掉；现在是**一层柔和色块光晕**（`.beat-glow`：`118vw × 44vh` 的径向渐变 + `blur(26px)`，固定贴底、不吃鼠标事件），音乐响度经 `decor.js` 写进 `:root` 的 `--beat`，CSS 用它驱动 `scale` 与 `opacity`。选它的理由：没有逐帧绘制，26 张卡片共用一次样式计算；音乐停了光晕退回静态底色，不会"看起来坏了"。

同一套机制还负责**滚动时的卡片节奏**：卡片中心离视口中心越远，`--sc`（缩放，最多 −5%）与 `--op`（不透明度，最多 −34%）越明显，于是滚动时中间清晰、上下两端自然淡出。只用两个自定义属性加 `transform/opacity`，因此不和 hover 位移、入场动画打架；屏外卡片直接跳过，`prefers-reduced-motion` 下完全不接管。

**加载页**：静态站点没有真实进度可报，所以不用进度条（那是撒谎），而是摆出**骨架屏**（顶栏 + 筛选条 + 卡片占位）——"马上会出现什么"比"还剩多少"更诚实。骨架卡按 `--i` 自上而下逐张铺开；`render()` 是整体替换 `#app.innerHTML`，所以加载快时骨架在同一帧就被真内容换掉（不拖时间），加载慢时骨架早已铺满、再由真内容淡入接上，节奏跟着真实速度走。

**侧栏"展开前后瞬移"的真正原因**：轨道态内容宽只剩 40px，面板标题与导航文字被挤成多行，每个条目都比展开态高一截，展开的一瞬间整列会上下跳 21px。修法不是微调间距，而是让**高度彻底不依赖宽度**：标题与标签锁成单行（文字本来在轨道态就是透明并被裁掉的），图标列 `flex: none` 钉死。现在 `check-round6.mjs` 会逐个条目对比两种状态的 y 坐标与高度，偏差必须为 0。

## 六、主动发现并处理的关键问题

### 关键问题：**"补充通知"导致的错误参与**

**发现过程**：逐条核对 26 条信息时，我注意到 01 与 09 讲的显然是同一个训练营 —— 01 说"原计划 9 月 20 日起每周六 19:00"，09 说"因场地调整，首次训练改为 9 月 21 日 19:30，地点改至实验楼 A402"。而 03 与 20 同样是招募补充说明（20 说明开发方向已满，只补设计与材料）。

**问题严重性**：如果按"一条信息一张卡片"平铺展示，新生刷到 01 后会记下"9/20 19:00"，等刷到 09 时很可能已经划过去了——**这是一次会真实发生的白跑**。同理，同学可能仍在准备投递 03 的"开发"岗位，而该岗位名额已满。

**处理方式**：
1. 在数据结构中为两条信息建立 `seriesId` 关联，并标记 `supplementOf`
2. 列表页**隐藏纯补充通知**（内容已并入主条目），避免同一件事出现两次造成混乱
3. 主条目被补充通知更新的字段（开始时间、地点）**以补充通知为准**覆盖
4. 详情页显著提示"本条已被补充通知更新"，并说明"上方显示的已是生效后的最新时间与地点"
5. 招募类条目额外标出 `已满：开发` / `仍在招：设计、材料`

**验证方式**：在逻辑层用固定时间点运行，确认条目 01 显示的开始时间为 `9月21日 19:30`、地点为 `实验楼 A402`，且列表页不再出现 09。

> 这个问题的价值在于：它**不在题目的显式要求里**，但它是 26 条材料中真实存在的陷阱，且会直接导致用户做出错误行为。发现并处理它，比多加几个功能更符合"减少用户判断成本"的创新定义。

## 九、开发说明

- **Git 提交**：按可运行里程碑提交（数据逻辑层 → 双端界面 → 发布与信息质量 → 视觉与文档 → 智能搜索 → 过渡动画 → 布局与收藏修复）
- **可回退性**：每个里程碑一次独立提交，任一步出问题可 `git revert` 回到上一个可用版本
- **提交前自检**（全绿才提交，避免"改 A 坏 B"）：
  ```bash
  node tools/verify-arch.mjs         # 架构自检（7 档分辨率）
  node tools/verify-render.mjs       # 渲染审查（要求：错误 0、警告 0）
  node tools/verify-interaction.mjs  # 交互验证（含动画几何、收藏跨层断言）
  node tools/check-search.mjs        # 搜索自检（召回 + 精度）
  node tools/check-readme.mjs        # 本文档自检
  node tools/check-live.mjs          # 线上实测（推送后 1~2 分钟再跑）
  ```
- **需要无头浏览器的四条**（先起本地服务器，沙箱需允许启动浏览器）：
  ```bash
  node tools/serve.cjs "$PWD" 8123
  node tools/check-layout.mjs                    # 逐宽度查横向溢出
  node tools/check-anim.mjs                      # 测展开/收起动画（默认 375/768/1440 三种形态）
  node tools/check-browser.mjs --width 375       # 真浏览器走用户路径
  node tools/check-round6.mjs                    # 底部光晕 / 侧栏不瞬移 / 滚动缩放淡出 / 骨架屏
  ```
  这四个工具补上了本地自检的盲区，并且各自抓到了真实缺陷：
  - `check-layout.mjs`：置顶通知条的"理由"原先用 `flex: none`，一整句中文无法收缩（固定约 354px），
    把整页在 320/360/375px 下分别撑出 64/25/10px 横向溢出，连 `position: fixed` 的底部导航与
    悬浮按钮都被推出屏幕 —— 这就是肉眼看到的"UI 错位"。
  - `check-anim.mjs`：打开详情时弹层 DOM 被重建了两次，第一次创建、正在播放展开动画的面板节点
    被第二次重建丢掉，动画等于没生效（面板"啪"地直接出现在终点）。本地 DOM 桩会因为复用面板对象
    而全绿，只有真浏览器测"面板真实矩形"才抓得到。
  - `check-browser.mjs`：验证「收藏 → 我的日程 → 刷新后仍在」这条跨层路径。
  - `check-round6.mjs`：侧栏"展开前后瞬移"的真实原因只有布局引擎能测出来 —— 轨道态内容宽
    只剩 40px，面板标题与导航文字被挤成多行，每个条目都比展开态高，于是展开瞬间整列上下跳。
    断言从"第一个图标 y 一致"升级为"**每一个**条目的 y 与高度在两态下偏差 ≤ 1px"，
    并把面板标题单行、图标 `flex: none` 一起锁成回归项。
    > 两个浏览器测试细节（都踩过）：无头浏览器**默认** `prefers-reduced-motion: reduce`，
    > 而本产品所有动画都尊重该偏好，不显式覆盖就只测到"减少动效"分支；
    > `Animation.setPlaybackRate` 必须在页面加载**之后**设置，否则会被导航重置。
- **敏感信息**：SSH 密钥等存放于 `_keys/`，已被 `.gitignore` 拦截，未进入公开仓库
- **部署**：GitHub Pages，`main` 分支 `/(root)` 直接发布，零构建

## 十、遗憾与缺陷
- **搜索**：已实现中文 / 拼音 / 首字母 / 近义词 / 错字容错五条匹配路径，但词库只覆盖校园场景里的常见说法，语料之外的生僻说法仍需要补词（维护约定见 `lexicon.js` 顶部注释）
- **动画**：详情弹层（二级卡片）按形态分两套——手机端是**贴底抽屉**（左右贴边、仅上方圆角、避开 home 指示条），
  电脑端是**居中对话框**（限宽 980px、四周留白）；两者共用同一份"从卡片位置长出来、收起时缩回卡片"的容器变换。
  真实浏览器实测：抽屉端 `left=0 / width=视口宽 / 底边=视口底`，电脑端面板中心与视口中心偏差 0px、
  留白 230/230；动画轨迹均从卡片尺寸连续长大到终点。
  但低端设备上非等比缩放仍可能掉帧，这一点没有条件实测
- **极端宽度**：320~1920px 共 10 档已实测无横向溢出；超出这个范围的超宽屏（>1920px）未逐档验证
- **真实设备**：以上结论均来自无头 Edge 的模拟视口与模拟触摸尺寸，尚未在真机（iOS Safari / 安卓各家浏览器）上复验
- 整体还有诸多不足
