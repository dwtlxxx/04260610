### 与 Steam++（Watt Toolkit）加速共存 —— 已解决

**推送不受影响**：本仓库用 SSH 推送，SSH 协议不经 TLS，Steam++ 的中间人代理拦不到。
即使 hosts 又把 `github.com` 指向 `127.0.0.1`，push 依然正常。

**HTTPS 类工具也修好了**，且**证书校验保持开启**（不是简单关校验）：

```
core.sshCommand   = ssh -F _keys/gh_ssh_config     # SSH 推送，不受加速影响
http.sslBackend   = openssl
http.sslCAInfo    = _keys/steamtools-ca.pem        # 显式信任 Steam++ 的自签证书
```

Steam++ 想开就开着，浏览 GitHub 照样加速；需要核验远端时用：

```powershell
powershell -ExecutionPolicy Bypass -File "tools\check-remote.ps1"
```

### 已解决的两个关键故障（现场若再遇到可照此排查）

| 故障现象 | 根因 | 解决 |
| --- | --- | --- |
| `Identity file D:/desktop/Computer not accessible`<br>`Host key verification failed` | Git 解析 `core.sshCommand` 时**不做引号处理**，只按空格切分；而工作区路径 `Computer progream` 含空格，导致 `-i` 收到被截断的路径 | 改为 `core.sshCommand = ssh -F _keys/gh_ssh_config`（零空格），密钥与主机密钥路径写进 ssh 配置文件内部 |
| 脚本报 `The string is missing the terminator` 等语法错误 | `.ps1` 文件无 UTF-8 BOM，Windows PowerShell 5.1 按 GBK 解析中文 | 两个脚本已保存为 UTF-8 with BOM |
