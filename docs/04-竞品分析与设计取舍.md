# 竞品分析与设计取舍

> 本文记录产品设计中的关键判断依据。对应考核要求中「主动发现并处理的一项关键问题」。

---

## 一、对标产品：校园圈子类社区（狐友 · 珠海科技学院）

考核期间参考了一款真实存在的校园社区产品，其结构为：

| 层级 | 内容 |
| --- | --- |
| 定位 | 校园社区 / 圈子，底部 Tab：圈子 · 发现 · 私信 · 我的 |
| 内容分区 | 圈子动态、二手集市、**组局**、评分 |
| 信息组织 | 「圈子动态」下再分标签：树洞、吐槽、表白、求助、交友… |
| 内容流 | 按时间 + 热度排序，有点赞、评论、浏览量、精华置顶 |
| 用户体系 | 头像、等级徽章（圈主 / 新生报道）、关注关系 |
| 发布 | 右下角悬浮按钮 |

**它的产品逻辑：以人和话题为中心，用社交互动把内容浮起来，让用户"逛"和"聊"。**

---

## 二、相同点

| 共同点 | 说明 |
| --- | --- |
| 面向同一批用户 | 在校学生，尤其新生 |
| 都支持开放发布 | 学生可自发发帖 / 组局，降低组织门槛 |
| 都重视新生引导 | 对方专门设有"新生解惑区" |
| 都是移动端优先的信息流 | 学生真实使用场景是手机 |
| 都需处理信息质量 | 对方靠版主 / 精华 / 举报，本产品靠规则引擎 |
| 都存在"约人组队"需求 | 对应题目第 22、23 条 |

---

## 三、核心差异：优化目标根本不同

> **圈子产品优化「注意力与讨论」；本产品优化「判断与行动」。**

| 维度 | 校园圈子 | 本产品 | 差异意味着什么 |
| --- | --- | --- | --- |
| 信息单元 | 帖子（自由文本 + 图片） | 结构化信息卡（标准字段） | 帖子表达自由但不可比较；信息卡可筛选、可排序、可判断 |
| 排序逻辑 | 时间 + 热度 | **截止时间紧迫度** | 热度浮起"有话题的"；本产品浮起"快截止且未报名的" |
| 核心动作 | 浏览 → 点赞 / 评论 | 浏览 → **判断 → 收藏 → 去报名** | 对方卖停留时长；本产品卖决策效率 |
| 权威信息 | 与普通帖混在同一条流 | 校 / 院发布 vs 学生自发**显式区分** | 题目明确要求合理呈现不同来源 |
| **更新关系** | 补充通知是**新的一条帖子** | 同一系列**自动合并**，只显示生效版本 | 见场景 1，这是最实在的差异 |
| 字段缺失 | 无字段概念，缺就缺了 | 显式标注"未注明" + 完整度评分 | 题目禁止编造，必须显式呈现未知 |
| 风险内容 | 靠人工运营，无客观标注 | 客观规则提示 + 完整度分 | 本产品给提示，不替用户下判决 |
| 可信度依据 | 社交声望（等级 / 圈主） | 来源类型 + 字段完整度 | 声望不等于准确，两者可互补 |

## 四、三个决定性的具体场景

### 场景 1：训练营改了时间地点（题 01 + 09）

- **圈子产品**：09 是一条新帖，01 是旧帖。新生刷到 01 记下"9/20 每周六 19:00"，划到 09 时可能已略过 → **跑错时间、跑错楼**
- **本产品**：两条同属一个 `seriesId`，详情页只显示生效的 **9/21 19:30 / 实验楼 A402**，并注明"本条已被补充通知更新"
- **本质**：圈子是"记录流"，本产品是"**当前事实**"

### 场景 2：可疑信息（题 24「零门槛、日结」+ 加私人微信）

- **圈子产品**：是一条正常帖子，有浏览有点赞，**无风险标识**
- **本产品**：仍然展示（保证开放发布），但**前置提示**"未提供主办方与地点" + 完整度低 + ⚠ 谨慎核实 + 举报入口
- **本质**：对方把判断责任完全交给用户；本产品从信息层面降低判断成本

### 场景 3：过期但仍有价值（题 19「报名已截止，现场有余位可候补」）

- **圈子产品**：文本里写着，但流里看不出状态，用户以为过期就不看
- **本产品**：状态机自动判为 **`可候补`**（而非"已截止"），并进入"仍可参与"筛选
- **本质**：对方展示**文本**，本产品推导**状态**

## 五、借鉴对方的优势（不做单方面贬低）

| 对方优势 | 本产品处理 |
| --- | --- |
| 社交互动（评论 / 点赞 / 私信）带来粘性 | **主动取舍**：不做私信 IM；改为轻量"提问 / 留言"，因题 23「报名后拉群」、题 16「有设备者优先」确有沟通需求 |
| 图片富媒体发布自然 | 受静态托管限制无法可靠存图，保持纯文本，但数据结构预留字段 |
| 二手集市 / 评分等成熟模块 | 判断为超纲，**明确不做**，避免大而全 |
| 运营手段（精华 / 置顶 / 版主） | 无人工运营，用**规则引擎**替代，形成差异化 |

## 六、由此产生的两项设计决策

### 决策 1：学生自发内容单独建模（组局卡）

原本打算把题 22、23 简单混入活动流，**这是错的**——它们与官方活动结构不同：

| | 官方活动 | 学生组局 |
| --- | --- | --- |
| 核心字段 | 截止时间、主办方、地点 | **人数、费用分摊、当前还缺几人** |
| 用户的问题 | 我能不能报、何时截止 | **还缺人吗、现在去来得及吗** |

→ 因此独立出「组局」视图与组局卡模板。**这是对标分析带来的最有价值启发。**

### 决策 2：明确产品定位边界

> **不做"校园社交场"，做"校园机会的决策面板"。**

定位清晰后取舍立刻明确：不追停留时长、不做私信、不做推荐算法，只把「这条信息能不能去、要不要去、怎么去」讲清楚。

## 七、双端形态与主题的架构取舍

| 维度 | 决策 | 理由 |
| --- | --- | --- |
| 双端表现 | **单页 + 运行时按断点渲染不同结构**，而非两套 HTML | 静态托管只能有一个入口；两套页面会产生两个网址、状态需维护两份，易不一致 |
| 手机端 | 卡片流 + 底部 Tab（成熟社交信息流形态，零学习成本） | 贴合碎片化浏览场景 |
| 电脑端 | 多列表格 + 常驻侧栏 + 筛选器平铺 | 一屏可见 12–15 条，支持排序与比较，才配得上"更全面的信息流" |
| 主题 | 默认**跟随系统**（浅色优先），支持手动三态切换 | 用户偏好优先，同时保留手动兜底（投影演示常需强制浅色） |
| 主题实现 | **设计令牌（CSS 变量）解耦** | 设备形态与主题正交，若混写将产生 2×2 共 4 套界面，无法维护 |

**关键约束**：内容结构只写两份（手机 / 电脑），颜色只写两份（浅色 / 深色），组合出四种表现。
